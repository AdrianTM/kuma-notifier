Kuma Notifier is an independent, read-only companion for Uptime Kuma. This submission targets desktop Firefox 140+ (Linux, macOS, Windows); Android is not selected for distribution.

BUILD
Extract the separate source ZIP and follow BUILD-FIREFOX.md: use Node.js 22 and npm, run npm ci, then npm run build. The Firefox extension is in dist/firefox/. esbuild bundles the JS modules without minification. All runtime dependencies are released npm packages pinned in package-lock.json. LICENSE and THIRD_PARTY_NOTICES.txt ship in the extension. No remote code or obfuscation is used.

ONE EXPECTED VALIDATOR WARNING
DANGEROUS_EVAL comes from the unmodified engine.io-client 6.6.8 globals.js fallback, which calls Function("return this")() only if both self and window are absent. Firefox background pages and Chrome service workers provide self, so that fallback is never executed in the supported extension environments. The extension CSP allows only script-src 'self' and does not allow unsafe-eval. The official dependency sources are left unchanged; build instructions reproduce this exact code. The app does not evaluate remote data or inject it as executable content.
Official packages: https://www.npmjs.com/package/socket.io-client/v/4.8.1 and https://www.npmjs.com/package/engine.io-client/v/6.6.8 . Bundled transitive package versions and licenses appear in THIRD_PARTY_NOTICES.txt.

DATA AND PERMISSIONS
The only mandatory API permissions are storage and alarms. HTTP/HTTPS hosts are optional so users can select their own Kuma installation; access is requested only for the selected host. Remote URLs must use HTTPS; plain HTTP is restricted to loopback for local testing. Notifications are optional. Firefox data consent declares required: ["none"], optional: ["authenticationInfo"]. Account connections request this permission before sending credentials, check it on each refresh, and clear the token/stop account polling on revocation. Public-page mode does not need it. Credentials go only to the configured Kuma server. No publisher endpoint, analytics, advertising, browser sync, or content scripts exist. See PRIVACY.md for the complete disclosure.

FUNCTIONAL TESTING WITHOUT EXTERNAL ACCESS
The source archive includes a loopback-only protocol fixture. After npm ci, run npm run reviewer:server. It prints the localhost URL (default http://127.0.0.1:3001). It is a test server, not a real Kuma deployment, and all its data and credentials are synthetic.
1. In extension Settings select Published status page. Paste http://127.0.0.1:3001/status/main and Save & connect. Approve the host permission and optional notifications. The popup shows Website and API server.
2. Open http://127.0.0.1:3001 in a normal browser tab to access the local fixture controls. Click Simulate outage, then Refresh in the extension. The badge becomes 1. Click Simulate recovery, then Refresh. Outage/recovery notifications depend on the OS notification service and the selected settings.
3. Search for a monitor; use the Problems filter. Click Snooze alerts to suppress notifications while keeping the badge live. Click Resume alerts to restore them.
4. Stop the fixture and Refresh to see the ? badge and cached results. Restart it to recover.
5. For a private connection, select Kuma login and enter http://127.0.0.1:3001, username demo, password fixture-password. These are public local-fixture credentials, not a real account. Approve authentication-information consent. Refresh to exercise saved-token login.
6. Revoke authentication-information consent in about:addons. Further account checks are blocked, the saved token is removed, and Settings offers reconnecting or using a public page. Disconnect & clear local data clears the configuration.
7. Optional: to test with real Kuma, run a disposable Uptime Kuma 2.5.11 instance locally, complete its initial setup with a throwaway account, add a monitor and publish a status page, then connect using the same flows. No access to the maintainer's private instance is required or provided.

Automated checks: npm test (core and Socket.IO adapter tests) and python3 scripts/firefox-smoke.py with geckodriver cover both connection methods, custom-domain slug discovery, saved settings, failed-login rollback, badge transitions, and authentication consent/revocation. Native OS notification delivery, signed-install restart behavior, and Android have not been verified by the headless suite.
