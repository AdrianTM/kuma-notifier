Kuma Notifier is an independent, read-only Uptime Kuma companion for desktop Firefox 140+ (Linux, macOS, Windows). Android is excluded.

UPDATE 0.1.2
Supersedes pending 0.1.1. Six reviewed fixes: restore missing polling alarms when the background wakes; alert on observed unknown/maintenance -> down; preserve alert history and notify during same-source settings saves; release previous host access after a successful switch; preserve current snooze/resume state when saving stale Settings; display/search authenticated group hierarchy. No new permissions or transmission categories. Clear/Show badge from 0.1.1 remains available.

BUILD
Extract the source ZIP, follow BUILD-FIREFOX.md, and run npm ci then npm run build using Node.js 22. Output: dist/firefox/. esbuild bundles unminified JS; package-lock.json pins released dependencies. LICENSE and THIRD_PARTY_NOTICES.txt are included. No remote code or obfuscation.

VALIDATOR WARNING
DANGEROUS_EVAL is in unmodified engine.io-client 6.6.8 globals.js: Function("return this")() is a fallback used only when both self and window are absent. Supported Firefox background pages and Chrome workers provide self, so it is not executed. CSP permits only script-src 'self', without unsafe-eval. Dependencies are unchanged; the source build reproduces the package exactly. Dependency versions/licenses are in THIRD_PARTY_NOTICES.txt.

DATA/PERMISSIONS
Mandatory: storage and alarms. Host access and notifications are optional. Remote URLs require HTTPS; HTTP is loopback-only. Data consent: required ["none"], optional ["authenticationInfo"]. Account mode requests consent before credentials, checks it each refresh, and removes the token/stops polling on revocation. Public mode needs no authentication consent. Data goes only to the chosen Kuma host. No publisher backend, analytics, ads, cloud sync, content scripts, or unrelated browsing access. See PRIVACY.md.

TESTING
After npm ci, run npm run reviewer:server. This loopback fixture uses synthetic data.
1. In Settings select Published status page and connect to http://127.0.0.1:3001/status/main. Approve host access/optional notifications. Two monitors appear.
2. Open http://127.0.0.1:3001. Simulate outage, then Refresh: badge 1. Clear badge hides it across refreshes; Show badge restores it. Recovery followed by another outage resets clearing. Test search, filter and Snooze/Resume alerts. Save an already-open Settings tab during snooze; it must remain snoozed.
3. Stop the fixture and Refresh: badge ? with cached results. Restart to recover.
4. Test Kuma login at the same base URL using demo / fixture-password (public fixture credentials). Approve authentication consent. Refresh uses the saved token. Revoking consent in about:addons blocks account checks and clears the token.
